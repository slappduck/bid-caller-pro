CURBCALL — WHAT CHANGED + HOW TO SHIP IT
==========================================

WHAT'S NEW
----------
1. MAP — after a scan, a "View Map" button appears on the Bids tab. Shows
   your search center (gold) and every scanned town, colored green (open
   bids there) or blue (scanned, nothing open right now).

2. NO MORE STALE BIDS — bids are now double-checked against their own
   deadline date, both on the server and in the app. If the date's
   already passed, it's treated as closed and won't show, even if the
   source page never marked it closed.

3. MORE BIDS ON THE BOARD — the scan now searches ~10 extra query
   patterns aimed at BidNet Direct, DemandStar, PlanetBids, Public
   Purchase, QuestCDN, OpenGov, Bonfire, CivicPlus/Municode — the actual
   platforms most cities post bids on — instead of just generic search
   terms.

4. UPCOMING WORK — the "Upcoming" tab (was already in the app but not
   wired to anything) now actually works: it searches council agendas,
   budgets, and capital improvement plans for sidewalk/ADA/curb work
   that's PLANNED but not yet an open bid, so you can get ahead of it.

5. GOOGLE SIGN-IN — the code for this was already correct (Supabase +
   Google OAuth, standard setup). This almost certainly isn't a code bug
   — see the checklist below.


PART A — DEPLOY THE WEBSITE FILES (Netlify, do this first, ~2 min)
--------------------------------------------------------------------
These 5 files: index.html, app.html, admin.html, terms.html, privacy.html

1. Go to app.netlify.com → your CurbCall/bidcaller site → Deploys tab.
2. There should be a drag-and-drop box near the top that says something
   like "Drag and drop your site output folder here" or "Deploy manually".
3. Drag all 5 .html files (or the whole folder) onto that box.
4. Netlify publishes it immediately — refresh bidcaller.netlify.app to
   check.

Note: this is a manual deploy, separate from the GitHub auto-deploy.
It's the fast path to get the new Map/Upcoming buttons live today.


PART B — DEPLOY THE BACKEND (GitHub → Render, do this too — the new
buttons won't actually work without it)
--------------------------------------------------------------------
These 2 files: license_server.py, requirements.txt

1. On your phone or computer, go to:
   github.com/slappduck/bid-caller-pro
2. Tap into "license_server.py" → pencil/edit icon → select all, delete,
   paste in the new version → "Commit changes" (commit straight to main).
3. Do the same for "requirements.txt".
4. Render will auto-redeploy in a minute or two (check the Render
   dashboard for the deploy to go green). Your existing API keys
   (OpenAI, SAM.gov, Supabase, etc.) stay exactly as they are — nothing
   to reconfigure there.


PART C — FIX GOOGLE SIGN-IN (dashboard settings, not code)
--------------------------------------------------------------------
Check these in order — one of these is almost certainly it:

1. Supabase Dashboard → Authentication → Providers → Google
   - Is it toggled ON?
   - Does it have a Client ID and Client Secret filled in? (Not blank,
     not a placeholder.)

2. Google Cloud Console → APIs & Services → Credentials → your OAuth
   Client ID
   - Under "Authorized redirect URIs", is this EXACT URL listed?
       https://novwdthapkorstdtloky.supabase.co/auth/v1/callback
   - If it's missing, add it and save.

3. Google Cloud Console → APIs & Services → OAuth consent screen
   - Is "Publishing status" still "Testing"? If so, ONLY email
     addresses you've explicitly added under "Test users" can sign in
     — everyone else gets blocked. Either add test users or publish the
     app (may require Google review for some scopes, but basic
     sign-in/email scope usually doesn't).

4. Supabase Dashboard → Authentication → URL Configuration
   - Is bidcaller.netlify.app (or https://bidcaller.netlify.app/app)
     listed under "Redirect URLs" / "Site URL"? If it only has
     localhost or a different domain, the redirect back from Google
     gets rejected.

Try signing in again after each fix — you'll usually see a clearer
error message in the small text under the Google button if something's
still off, which narrows it down further.
